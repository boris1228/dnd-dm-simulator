# Skill_Check_Rules — 技能检定触发系统

## 被动检定（Passive Checks）——DM 主动触发，无需玩家要求

每次描述新场景/新 NPC/新物品时，DM 内部对照玩家角色的被动值，符合条件自动触发并写入描述：

| 被动技能 | 触发时机 | 公式 |
|----------|----------|------|
| 被动感知 (Perception) | 场景中有隐藏物、伏击、异常声响/气味 | 10 + WIS修正 + 熟练(如有) |
| 被动奥秘 (Arcana) | 接触魔法现象、附魔物品、法术痕迹 | 10 + INT修正 + 熟练(如有) |
| 被动历史 (History) | 接触古代遗迹、历史事件相关线索 | 10 + INT修正 + 熟练(如有) |
| 被动调查 (Investigation) | 犯罪现场、逻辑线索、机关痕迹 | 10 + INT修正 + 熟练(如有) |
| 被动洞悉 (Insight) | NPC 说谎、隐瞒情绪、异常行为 | 10 + WIS修正 + 熟练(如有) |

**输出格式**：

```
`[被动奥秘 DC13 ✓]` 你注意到墙上的符文并非装饰——它们仍在微弱地脉动。
`[被动洞悉 DC12 ✗]` 老板娘的语气听起来很正常。
```

- 成功：给出真实、有用的信息，不含糊
- 失败：不告知"你检定失败了"，只是不给出额外信息，或给出误导性的表层信息（不撒谎，但不主动揭示）
- DC 由 DM 根据线索的隐藏程度设定（简单 DC10 / 中等 DC13 /困难 DC16 / 极难 DC19+）

## 主动检定（Active Checks）——玩家宣告行动后触发

玩家明确宣告一个需要检定的行动时（搜查、说服、攀爬、撬锁等），DM：

1. 明确要求或代掷骰子
2. 公布 DC（除非该 DC 对世界内角色而言也是未知的，可以先掷后公布）
3. 描述结果，成功和失败都要有具体后果，失败不等于"什么都没发生"

**格式**：

```
[请掷 说服(Persuasion) d20，加上你的加值]
```

或代玩家掷（如果玩家要求或规则允许）：

```
[说服 d20=11+(-1)=10 vs DC13 ✗] 卫兵翻了个白眼，"少来这套。"
```

### 失败的意义

失败应该推动剧情往新方向发展，而不是卡住流程：
- 说服失败 → NPC 起疑，或提出更高要价
- 侦查失败 → 错过线索，但可能触发其他事件（被发现在窥探）
- 攀爬失败 → 摔落受伤，或吸引怪物注意

## 环境互动原则

每个场景至少埋 **3 个可互动元素**，通过描述自然带出，不要用"你可以检查xxx"这种游戏化提示：

> ❌ "房间里有一张桌子，你可以搜索它。"
> ✅ "桌上散落着几封没拆封的信，蜡封上的纹章你有些眼熟。"

玩家自己决定要不要去查、去问、去碰。
